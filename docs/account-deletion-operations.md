권장 기준은 아직 확정된 SLA나 구현 완료 기능이 아니다.

## 먼저 결정할 것

- [ ] 네이버 메일 알림을 휴대폰에서 켜고 별도 테스트 메일의 수신 확인.
- [ ] 접수 후 24시간 내 안내, 본인 확인 후 지체 없이 처리(권장 목표 3일 이내)를 실제로 지킬지 결정.
  외부 업체 보관 로그까지 이 기간에 삭제한다고 약속하지 않는다.
- [ ] 앱에 접근할 수 없는 사람의 계정 소유권을 확인할 수단 결정·구현.
  현재 이메일 주소는 계정에 저장되지 않으므로 발신 주소·이름·역할만으로 확인 불가.
  다른 사용자의 답변 내용이나 가족만 아는 정보로 소유권을 추정하지 않는다.
  후보: 웹 카카오 로그인으로 동일 서비스의 카카오 식별자를 서버에서 검증.
  이는 아직 구현되지 않았으며 별도 웹 인증·계약·보안 검토가 필요하다.
- [ ] 운영자 삭제 실행 수단 결정·검증. 현재 DELETE /users/me는 본인 access token용이다.
  사용자 토큰을 이메일로 받거나 임의 JWT를 발급하거나 TRUNCATE/수동 행 삭제로 대신하지 않는다.
  기존 AccountDeletionService의 본인 기여 삭제·R2 큐·카카오 해제·상대 기록 보존을 지키는 제한된 관리 절차가 필요하다.
- [ ] 요청 메일과 운영 기록의 별도 보관 기간·삭제 방식을 결정하고 처리방침 수집/보관 항목에 반영.
  문의 메일도 개인정보이며 무기한 보관하지 않는다. 네이버 메일을 통한 처리 범위·제공업체 조건도 확인한다.

## 확정 후 반복할 절차

1. 요청 접수 후 내부 요청 번호를 부여하고 접수 안내 회신.
2. 필요한 최소 정보로 승인된 본인 확인 절차 실행. 확인 전에는 계정 정보·존재 여부를 회신하지 않음.
3. 본인 확인 완료 후 삭제 범위·복구 불가 안내와 삭제 의사 확인.
4. 검증된 운영자 경로로 삭제 요청. 권한 제한·감사 기록을 유지.
5. 요청 COMPLETED, 남은 작업 없음, 본인 DB 내용·R2 대상 파일 삭제와 카카오 해제 확인.
   재시도 중이면 완료라고 회신하지 않음. 로그·URL·토큰을 메일에 붙이지 않음.
6. 완료 안내. 지연 시 사유·다음 안내 예정 시점을 회신하고 담당자가 추적.
7. 정한 보관 기간이 지나면 메일·최소 처리 기록을 파기.
