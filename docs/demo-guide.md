# 시연 가이드 — 10/2 MVP

금요일 시연을 처음부터 끝까지 따라 할 수 있게 정리한 문서다. 서버를 어디에 둘지가
정해지면 [2. 서버 준비](#2-서버-준비)의 주소만 채우면 된다.

- 대상 기기: **안드로이드 폰 2대**(부모·자녀). 폰이 한 대뿐이면 자녀는 노트북 에뮬레이터로 한다.
- 아이폰은 이번 시연에서 지원하지 않는다. (`ios/` 없음, Android만 MVP 대상)
- 예상 시간: 준비 30분, 시연 3~4분

## 1. 시연 순서

| # | 누가 | 화면에서 할 일 | 보여줄 점 |
|---|---|---|---|
| 1 | 자녀 폰 | 앱 열기 → **자녀예요** → 이름 입력 → 시작하기 | 가입은 역할과 이름뿐. 첫 화면의 "연결된 두 분만 듣고 볼 수 있어요" |
| 2 | 자녀 폰 | 초대 숫자 확인 → **부모님께 보내기** | 카톡 공유 창이 뜬다 (시연에서는 숫자를 불러 줘도 된다) |
| 3 | 부모 폰 | 앱 열기 → **부모님이에요** → 이름 → 숫자 6자리 → 연결하기 → **연결 되었어요!** → 시작하기 | 부모님은 숫자만 입력. 자녀 폰도 **저절로** "연결 되었어요!"로 바뀐다 → 시작하기로 오늘 질문 |
| 4 | 자녀 폰 | 답하기 → 글 입력 → 답변 보내기 → 홈으로 | "부모님이 답하시면 여기에서 들을 수 있어요" |
| 5 | 부모 폰 | 목소리로 답하기 → 말하기 시작 → 30초 안쪽으로 말하기 → 그만 말하고 보내기 | 버튼 3번. 녹음이 글로 정리된다 |
| 6 | 자녀 폰 | **아무것도 누르지 않고** 기다린다 (10초 안) | 서로 답하면 공개. 부모님 답이 정리된 글로 나타난다 |
| 7 | 부모 폰 | 오늘 화면으로 → 자녀의 답 확인 | 부모 쪽도 공개 |

5번에서 말할 거리: 질문에 맞는 짧은 기억 한 가지. 녹음은 1~60초만 받는다.

## 2. 서버 준비

폰이 접속할 백엔드가 필요하다. **둘 중 하나**를 고른다.

### A. 배포 서버 (정해지면 채움)

- 주소: `https://____________/api/v1`
- 확인: 폰 브라우저에서 `https://____________/api/v1/health` → `{"status":"UP",...}`
- A를 쓰면 3장의 빌드에서 `API_BASE_URL`만 이 주소로 바꾸면 된다.

### B. 노트북에서 백엔드 실행

폰과 노트북이 **같은 네트워크**에 있어야 한다. 학교·공용 Wi-Fi는 기기끼리 통신을
막는 경우가 많으니 **폰 핫스팟**에 노트북과 두 폰을 모두 붙이는 것이 안전하다.

```bash
cd backend
cp .env.example .env        # 처음 한 번
docker compose up -d        # PostgreSQL
set -a; source .env; set +a
./gradlew bootRun
```

- `.env`의 `APP_JWT_SECRET`은 처음 한 번 `openssl rand -hex 32` 값으로 바꾸고, **시연 전후로 다시 바꾸지 않는다.** 바뀌면 폰에 저장된
  로그인이 모두 무효가 되어 가입 화면으로 돌아간다(7장).
- AI 처리는 기본이 Mock이다. 실제 정리 결과를 보여주려면 `backend/README.md`의
  "실제 음성 처리 활성화" 값(OpenAI, R2)을 넣는다.

노트북 주소 확인:

```bash
ipconfig getifaddr en0      # macOS
```

Windows는 `ipconfig`의 "무선 LAN 어댑터 Wi-Fi → IPv4 주소"를 본다. 이 주소를 `<노트북IP>`라고 부른다.

폰 브라우저에서 `http://<노트북IP>:8080/api/v1/health`가 열려야 한다. 안 열리면 7장을 본다.

## 3. 앱 빌드와 설치

`frontend/`에서 서버 주소를 넣어 **debug APK**를 만든다.

```bash
cd frontend
flutter build apk --debug --dart-define=USE_MOCK=false --dart-define=API_BASE_URL=http://<노트북IP>:8080/api/v1
```

> **B(노트북 서버, http)는 반드시 debug APK로 만든다.** http 접속 허용은
> `android/app/src/debug/AndroidManifest.xml`에만 있어서 release APK는 http 서버에
> 모든 요청이 실패한다. A(https 배포 서버)라면 release도 된다.

설치(폰을 USB로 연결하고 USB 디버깅 허용):

```bash
adb install -r build/app/outputs/flutter-apk/app-debug.apk
```

- 폰마다 한 번씩 한다. `adb devices`로 폰이 보이는지 먼저 확인한다.
- debug APK는 약 200MB라 카톡 전송보다 USB 설치가 낫다. 파일로 보낼 때는 폰에서
  "출처를 알 수 없는 앱 설치"를 허용해야 한다.
- 처음 녹음할 때 마이크 권한을 **허용**한다.

## 4. 시연 직전 체크리스트

- [ ] 서버 `/health`가 **두 폰의 브라우저에서** 열린다
- [ ] 두 폰 모두 같은 네트워크(핫스팟)에 붙어 있다
- [ ] 두 폰의 앱 데이터를 지웠다: 설정 → 앱 → 들려줘요 → 저장공간 → 데이터 삭제
      (또는 `adb shell pm clear com.apptive.life_record`)
- [ ] 오늘 날짜에 질문이 있다. 질문은 `backend/src/main/resources/seed/mock-questions.json`에
      **10/2까지** 들어 있다. 시연이 미뤄지면 날짜를 추가한다.
- [ ] 리허설을 한 뒤라면 **새로 가입**한다. 앱 데이터를 지우면 새 기기로 보고 새 가족이
      만들어지므로, 같은 날에도 답하기 전 상태부터 다시 보여줄 수 있다.
- [ ] 폰 화면 자동 꺼짐을 길게, 방해 금지 모드 켜기
- [ ] 노트북 절전 끄기 (B 방식이면 노트북이 꺼지면 서버도 꺼진다)

## 5. 서버가 안 될 때: Mock으로 대신하기

서버 없이 폰 한 대로 화면 흐름만 보여주는 방법이다. 두 폰이 실제로 이어지지는 않는다.

```bash
flutter build apk --debug                                   # 기본이 Mock
flutter build apk --debug --dart-define=MOCK_TODAY=revealed  # 공개된 홈부터
```

- Mock에서는 자녀 초대 화면이 **8초 뒤 자동으로 연결**된다.
- 홈 상태는 `MOCK_TODAY` 값으로 고른다(`assets/mocks/today_*.json`): `waiting_for_both`(기본),
  `waiting_for_parent`, `waiting_for_child`, `revealed`(자녀 화면), `parent_revealed`(부모 화면)
- 여러 상태를 보여줘야 하면 APK를 상태별로 만들어 두거나, 노트북에서
  `flutter run --dart-define=MOCK_TODAY=...`로 바꿔 가며 띄운다.

## 6. 알려진 제한

2026-09-28 기준. 해결되면 이 표에서 지운다.

| 기능 | 상태 | 시연에서 |
|---|---|---|
| 지난 이야기 (`GET /stories`) | 백엔드 미구현 → 오류 화면 | 누르지 않는다 |
| 자녀 답을 목소리로 듣기 (TTS) | 백엔드 미구현 → "문제가 생겼어요" | 부모 쪽은 글 답만 보여준다 |
| 부모님 목소리 듣기 (원본 재생) | `STORAGE_TYPE=r2`일 때만 링크가 생긴다. 로컬 저장이면 버튼이 안 보인다 | R2 설정이 없으면 정리된 글만 보여준다 |
| 녹음 정리 결과 | `AUDIO_PROCESSING_MODE=mock`이면 "Mock으로 정리된 이야기입니다." | 실제 결과가 필요하면 OpenAI 키를 넣는다 |
| 에뮬레이터 | 이 팀 노트북들에서 앱 시작에 10초 이상 걸린 적 있음 | 가능하면 실제 폰 |

## 7. 문제 해결

| 증상 | 원인과 해결 |
|---|---|
| 가입에서 "인터넷 연결을 확인해 주세요" | 폰 브라우저로 `/health` 확인. 안 열리면 네트워크가 다르거나 방화벽. Windows는 방화벽에서 Java(8080) 인바운드 허용, macOS는 방화벽 허용 창에서 허용 |
| `/health`는 열리는데 앱만 실패 | release APK로 http 서버에 붙은 경우. debug APK로 다시 빌드 |
| 앱이 가입 화면으로 돌아가며 "다시 시작해 주세요" | 서버의 `APP_JWT_SECRET`이 바뀌었거나 DB를 지웠다. **같은 역할**로 다시 가입하면 된다 |
| "오늘 질문을 준비하고 있어요" | 오늘 날짜의 질문이 없다. `mock-questions.json`에 날짜 추가 후 서버 재시작 |
| 숫자 입력 시 "이미 사용된 숫자예요" | 리허설에서 쓴 숫자. 자녀 앱 데이터를 지우고 새로 가입 |
| 자녀 폰이 공개 화면으로 안 바뀜 | 10초 정도 기다린다. 급하면 홈을 아래로 당겨 새로고침 |
| "마이크 권한이 필요해요" | 처음 물었을 때 거부했다. 설정 → 앱 → 들려줘요 → 권한 → 마이크 허용 |
