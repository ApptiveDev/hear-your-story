# 출시 QA 실행과 결과 기록

## 실행 기준

설치한 APK/AAB의 버전·빌드 번호·커밋과 서버 환경/버전을 먼저 기록한다.
Mock 검증과 실제 서버 검증을 분리하며, 준비되지 않은 기능은 PASS 대신 BLOCKED로 둔다.
서버 작업 중단·토큰 만료·삭제 검증은 담당자와 합의한 테스트 환경과 데이터로만 실행한다.

## 실행 환경과 역할

| 구분 | 확인 범위 | 기록 기준 |
|---|---|---|
| Android 에뮬레이터 | 화면 이동, 버튼 상태, 큰 글씨, 미리 듣기·전송 흐름 | 에뮬레이터 모델/API 수준과 Mock 여부 기록 |
| Android 실기기 | 실제 녹음·재생 품질, 멈춤·재개 후 파일, 전화 수신·백그라운드 중단, 버튼·탭 막대 표시 | 기기 모델·Android 버전과 실행자 기록 |
| 실제 서버 연동 | 인증·페어링·업로드·삭제·기록 갱신 | 서버 버전과 기능 활성화 설정 기록. Mock 결과와 분리 |

실제 서버 연동은 에뮬레이터와 실기기에서 각각 실행할 수 있다. 에뮬레이터나 Mock에서
통과한 결과로 실기기·실제 서버 항목까지 PASS 처리하지 않는다.
실기기가 없는 검증자는 테스트 항목·기대 결과와 빌드 정보를 Android 기기를 가진
실행자에게 전달하고, 받은 결과와 버그를 취합해 수정 후 재검증을 관리한다.

- `NOT_RUN`: 아직 실행하지 않은 항목. 체크리스트 작성이나 CI 통과만으로 변경하지 않는다.
- `BLOCKED`: 기기 미확보·서버 미배포·인증 설정 미준비 등으로 실행할 수 없는 항목. 이유를 적는다.
- `PASS` / `FAIL`: 해당 환경에서 직접 실행한 관찰 결과가 기대 결과와 일치하는지로 판정한다.

## 검증 시나리오

| ID | 시나리오 | 확인할 결과 |
|---|---|---|
| Q01 | 설치·앱 재시작 | 설치 성공, 대상 환경에서 의도한 시작 화면 |
| Q02 | 부모·자녀 가입·페어링 | 양쪽이 같은 Pair로 연결, 잘못된/만료된 코드 안내 |
| Q03 | 마이크 거부→허용 | 거부 안내 후 권한 허용 시 녹음 가능 |
| Q04 | 녹음→멈춤→이어가기 여러 번 | 파일 하나로 재생, 멈춘 시간 제외, 중복 업로드 없음 |
| Q05 | 멈춤→처음부터 다시 말하기 | 취소하면 기존 녹음 유지, 확인하면 이전 음성 제거·시간 초기화 |
| Q06 | 실제 녹음 합계 60초 | 멈춘 시간 제외. 60초에 자동 종료 후 미리 듣기로 이동하며 보내기 전 업로드 없음 |
| Q07 | 전화·백그라운드 전환 | 의도하지 않은 전송 없음, 복귀 후 파일/상태 확인 |
| Q08 | 업로드 중 네트워크 단절→복구 | 오류/재시도 가능, 같은 답 중복 생성 없음 |
| Q09 | 부모 음성·자녀 글 제출 | 양쪽 제출 전 비공개, 제출 후 공개·원본·요약·TTS 확인 |
| Q10 | 오디오 URL 만료 후 재생 | 새 URL로 재생, 무한 로딩/중복 재생 없음 |
| Q11 | 월별 달력 | 다른 달·빈 달·날짜 선택·월 복귀, 양쪽 역할의 음성 재생 |
| Q12 | 글씨 1.3배·2배 | 주요 버튼 접근 가능, 안내/본문 잘림 없음 |
| Q13 | 카카오 로그인·만료·재설치·기기 변경 | 확정된 인증 API의 대상 서버 배포 확인 후 실행. 신규 가입·토큰 회전 갱신·같은 계정의 Pair·기록 복구 |
| Q14 | 회원 탈퇴 | 프론트 연동과 서버 배포 확인 후 실행. 토큰 차단·Pair 해제·본인 자료 삭제·상대 기록 보존·재페어링, DB/R2 결과는 담당자와 확인 |
| Q15 | 마이페이지 | 로그아웃, 처리방침·문의·버전과 실제 빌드 일치 |
| Q16 | 내 답 개별 삭제 (부모·자녀 각각) | 대상 서버에 계약 5.12·5.15 배포 확인 후 실행. 본인 답만 삭제되고 질문·상대 답 보존. 홈·책장·달력 및 앱 재실행 후 삭제 안내, 삭제된 답의 재생·재작성 차단. DB·파일 삭제 결과는 담당자와 확인 |
| Q17 | 수동 정지 / 일시정지 후 정지 → 미리 듣기 | 방금 녹음한 파일 재생 가능. 보내기를 누르기 전 업로드 없음 |
| Q18 | 미리 듣기 없이 보내기 / 재생 중 보내기 연타 | 듣기는 선택. 재생 중이면 멈춘 뒤 전송하고 중복 업로드·답 생성 없음 |
| Q19 | 미리 듣기 → 다시 녹음 | 취소 시 기존 파일 유지. 확인 시 이전 음성 제거·시간 초기화, 새 녹음만 재생·전송 |

Q16은 회원 탈퇴와 별개이며 API는 구현되어 있다. 앱과 서버가 같은 삭제 계약을
사용하는지 확인하고, 서버가 미배포 상태라면 그 이유로 BLOCKED를 기록한다.
파일 삭제는 비동기이므로 기존 서명 URL이 즉시 무효화된다고 판정하지 않는다.
삭제 범위·오류·파일 삭제 재시도 기준은 [API 계약](api-contract.md)의 5.12·5.15를 따른다.

## 결과 양식

아래를 테스트 PR 본문 또는 팀이 합의한 QA 기록에 복사한다.
녹음 원문, 개인 계정 정보, 토큰, 서명 URL, 서버 비밀값은 첨부하지 않는다.

```text
검증 일시 / 검증자:
실행자 (검증자와 다를 때):
앱 버전+빌드 번호 / 커밋:
환경 이름 / 서버 버전:
부모 실행 환경 (실기기/에뮬레이터)·모델·Android 버전/API 수준:
자녀 실행 환경 (실기기/에뮬레이터)·모델·Android 버전/API 수준:
활성화된 기능 / Mock 여부:

ID | PASS / FAIL / BLOCKED / NOT_RUN | 관찰 결과 또는 차단 사유 | 버그 링크 | 재검증 빌드
Q01 | NOT_RUN | | |
```

버그는 재현 순서, 기대 결과, 실제 결과, 발생 빈도와 영향을 적는다.
로그·스크린샷에서 민감정보를 가린 뒤 첨부한다. 수정 PR이 병합돼도 같은 시나리오를
새 빌드에서 재검증하기 전에는 검증 완료로 바꾸지 않는다.

## 빌드 배포 기록

| 배포일 | 앱 버전/번호 | 소스 커밋 | 환경/서버 버전 | 설치 파일 SHA256 | 배포 채널 | QA 결과 |
|---|---|---|---|---|---|---|

설치 파일 해시와 커밋은 빌드 스크립트가 생성한 `build-info.json`에서 가져온다.
CI 통과와 APK 생성은 실기기 검증을 대신하지 않는다.
